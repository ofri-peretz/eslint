## Why this rule exists

ESLint Rule: no-log-injection
Detects attacker-controlled values concatenated into a log *message*.
CWE-117: Improper Output Neutralization for Logs

A log file is a record with line boundaries. When a request field reaches the
message text unneutralized, a `\r\n` inside that field ends the record early
and starts a new one the attacker writes:

  logger.info('login attempt: ' + req.body.username)
  // username = "bob\n[INFO] login ok for admin"

The forged line is indistinguishable from a real one to every downstream
consumer — SIEM rules, on-call greps, incident timelines.

@see https://cwe.mitre.org/data/definitions/117.html
@see https://owasp.org/www-community/attacks/Log_Injection

## True positives — what it catches

8 asserted case(s). These are the claims; each is only as good as the case.

- console.error with a template — `'console.error('bad path ${req.path}');'`
- a logger held on  — `'class S { handle(req) { this.logger.warn("q=" + req.query.q); } }'`
- a framework logger reached through a property — `'fastify.log.info('url=${request.url}');'`
- a computed request property with a non-literal key still counts — `'logger.info("h=" + req.headers[name]);'`
- a template nested inside a concatenation — `'logger.warn("ctx " + 'user=${ctx.params.id}');'`
- a lambda event body — `'logger.info('payload=${event.body}');'`
- loggerNames adds a receiver — `'audit.info("user=" + req.body.username);'`
- requestRoots adds a request root — `'logger.info("id=" + payload.body.id);'`
