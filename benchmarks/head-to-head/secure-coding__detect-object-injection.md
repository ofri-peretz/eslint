## `eslint-plugin-security/detect-object-injection` against its own contract

Their documentation: *"flags any expression in the form of `object[expression]` no matter where it occurs"*

<https://github.com/eslint-community/eslint-plugin-security/blob/main/docs/rules/detect-object-injection.md>

Every form below is that shape.

| form | theirs | ours |
|---|---|---|
| identifier key (their own doc example) — `o[key] = v;` | 1 | 1 |
| member key — `o[req.query.p] = v;` | **missed** | 1 |
| nested index — `o[parts[i]] = v;` | 1 | 1 |
| call result — `o[f()] = v;` | **missed** | 1 |
| template literal — `o[`${a}`] = v;` | **missed** | 1 |
| concatenation — `o[a + b] = v;` | **missed** | 1 |
| conditional — `o[c ? a : b] = v;` | **missed** | 1 |
| await — `async function g(){ o[await k()] = v; }` | **missed** | 1 |
| assignment in key position — `o[(k = x)] = v;` | **missed** | 1 |
| comma expression — `o[(a, b)] = v;` | **missed** | 1 |
| optional call — `o[f?.()] = v;` | **missed** | 1 |

**9 of 11** documented forms are not reported by their rule.

## Read this before quoting the numbers

**We wrote this battery.** A score on a set chosen by the rule’s own authors
measures the authors. It is a floor on how we handle cases we thought of, not
a measurement of the rule in the world.

### What we still get wrong

- A TS enum used as a key reports. A closed set, but deciding that needs the type, and these rules are type-unaware by policy.
- A bare parameter used as an index reports. Deliberate: the name-based version of this cleared `function put(o, k) { o[k] = 1 }`, which is the defect itself.
- `o[String(i)] = 1` reports. `String()` of an arbitrary parameter can produce any string.

### Discarded rather than counted

- `o?.[k] = 1` — invalid JavaScript, you cannot assign through an optional chain. It read as a miss until it was run.
