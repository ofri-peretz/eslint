## Rule Details

This rule detects when MongoDB connection options contain hardcoded `user`, `username`, `pass`, `password`, or `auth` values. `authSource` names the database that holds the users, not a secret, so a literal one is not reported.

### ❌ Incorrect

```typescript
// Hardcoded credentials in options object
mongoose.connect(uri, {
  user: 'admin',
  pass: 'secretPassword123',
});

// MongoClient options
const client = new MongoClient(uri, {
  auth: {
    username: 'admin',
    password: 'hardcodedSecret',
  },
});
```

### ✅ Correct

```typescript
// Use environment variables
mongoose.connect(uri, {
  user: process.env.MONGO_USER,
  pass: process.env.MONGO_PASS,
});

// Use config module
const client = new MongoClient(uri, {
  auth: {
    username: config.db.user,
    password: config.db.pass,
  },
});
```

### Query filters, updates and pipelines

A `user`, `username` or `auth` value written inside a query filter, an update
document or an aggregation stage is the account being looked up or written. It
is not a login. A Mongo data operation (`find*`, `update*`, `delete*`,
`replaceOne`, `countDocuments`, `distinct`, `exists`, `aggregate`) that gets the
object, either inline or through a `const`, makes it data, so those keys are not
reported there. A literal `pass` / `password` is still a hardcoded secret
wherever it is written, so it is still reported in a filter or an update.

```typescript
// ✅ a lookup value, not a credential
await User.findOne({ username: 'admin' });
await User.aggregate([{ $match: { username: 'admin' } }]);
await User.updateOne({ username: 'old' }, { $set: { username: 'admin' } });

// ❌ still reported: a hardcoded password, even in a filter
await User.findOne({ username: 'admin', password: 'hunter2' });
```

## Known False Negatives

### Variables with Hardcoded Values

```typescript
// ❌ NOT DETECTED - hardcoded in variable, used in options
const password = 'secret';
mongoose.connect(uri, { pass: password });
```

## When Not To Use It

- In test files with test database credentials
- In development with local-only test databases
