## Rule Details

A Lambda handler (a function taking the event) that performs a privileged
operation — a database write or delete, an AWS SDK `send`, an SDK v2
DocumentClient / S3 mutation, a Lambda invoke — is reported unless the
function contains an authorization check. The rule does not check whether
that check runs before the operation. The check may be:

- reading the authorizer's verdict off the event: Cognito
  `requestContext.authorizer.claims`, HTTP API JWT `requestContext.authorizer.jwt.claims`,
  a Lambda authorizer's context, IAM `requestContext.identity`;
- reading the `Authorization` header to verify it;
- an identity field (`sub`, `userId`, `isAdmin`, …) read off something other
  than client input, or an early `401` / `403` return.

A value the client sent is not identity, whatever it is called:
`event.pathParameters.userId`, or a field of a local parsed from the body
(`const payload = JSON.parse(event.body)`), does not count as an authorization
check. Work that reaches nothing outside the process
(arithmetic, a `new Map()` cache) needs no authorization.

## Examples

### ❌ Incorrect

```javascript
// Lambda handler performs a privileged operation without checking caller identity
export const handler = async (event) => {
  await db.query('DELETE FROM users');
};
```

### ✅ Correct

```javascript
// Verify authorization before performing sensitive operations
export const handler = async (event) => {
  const user = event.requestContext?.authorizer?.claims;
  if (!user?.sub) {
    return { statusCode: 403, body: 'Forbidden' };
  }
  await db.query('DELETE FROM users WHERE id = $1', [user.sub]);
};
```

## Configuration

```javascript
{
  rules: {
    'lambda-security/no-missing-authorization-check': 'warn'
  }
}
```
