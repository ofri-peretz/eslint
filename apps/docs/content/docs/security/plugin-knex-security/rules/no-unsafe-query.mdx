## Rule Details

Reports three shapes when they reach a raw-SQL sink:

1. String concatenation — `knex.raw('SELECT ... ' + value)`
2. Template interpolation — ``knex.raw(`SELECT ... ${value}`)``
3. A variable tainted by either, including via `+=`, then passed to a sink

### Sinks

`knex.raw()` and `.raw()` on a query builder.

### ❌ Incorrect

```typescript
await knex.raw(`SELECT * FROM users WHERE id = ${userId}`);

await knex.raw('SELECT * FROM users WHERE email = ' + email);

let sql = 'SELECT * FROM products WHERE 1=1';
sql += ` AND name = '${name}'`;
await knex.raw(sql);
```

### ✅ Correct

```typescript
knex.raw('SELECT * FROM users WHERE id = ?', [userId]);
```

## Known limitations

- A method chosen at runtime — `knex[verb](...)` — names nothing to
  match against the sink list, so it is not reported. The quoted spelling
  `knex['raw'](...)` names `raw` and IS reported.
- Taint tracking is single-scope and name-based — it does not follow a query
  string across function boundaries.

## Implementation

The detection is shared across the driver plugins via `createSqlInjectionRule`
in `@interlace/eslint-devkit`; this rule supplies Knex's sinks and
remediation copy. Install the plugin matching your stack and you get exactly
one finding per line.
