❌ This rule is deprecated. It was replaced by [`first`](./first).

`imports-first` is the old name of [`first`](./first). eslint-plugin-import 2.32.0 still exports it, deprecated, as `first` with a deprecated `meta`; this plugin does the same. It reports what `first` reports, for the same options. Use `first` in new configs.

## Rule Details

| Aspect         | Details                                                               |
| :------------- | :-------------------------------------------------------------------- |
| **Status**     | Deprecated (`meta.deprecated: true`), replaced by [`first`](./first) |
| **Reports**    | Exactly what `first` reports, with the same options                   |
| **In presets** | No preset enables it                                                  |
| **Options**    | The same as `first`: `"absolute-first"` or `"disable-absolute-first"` |

## Why it exists

A config that registers this plugin under the `import` key and names `import/imports-first`, or a `// eslint-disable-next-line import/imports-first` comment, would otherwise stop ESLint with "Could not find rule". With this entry it loads and behaves as `first`.

## Configuration

```javascript
// eslint.config.js
import importNext from 'eslint-plugin-import-next';

export default [
  {
    plugins: { 'import-next': importNext },
    rules: { 'import-next/imports-first': 'error' },
  },
];
```

Prefer the replacement:

```javascript
rules: { 'import-next/first': 'error' }
```
