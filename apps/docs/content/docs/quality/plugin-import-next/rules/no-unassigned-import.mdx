## Rule Details

An import that binds nothing is loaded only for its side effects, which a reader cannot see. Reported: `import 'm'`, `import {} from 'm'`, and a `require('m')` whose result is discarded (an expression statement, or a non-final item of a sequence).

Not reported: any form that binds or re-exports a name (default, namespace, named, type-only, `export … from`, a `require` whose result is used, `import x = require()`), specifiers listed in `allowModules` (exact match), and specifiers matched by a glob in `allow`.

### ❌ Incorrect

```ts
import './polyfill';
import {} from './setup';
require('./register');
```

### ✅ Correct

```ts
import { install } from './polyfill';
const register = require('./register');
// with { allowModules: ['./polyfill'] }
import './polyfill';
```

### eslint-plugin-import options

A config carried over from `import/no-unassigned-import` loads, and its
options mean what they meant there:

- `allow`: globs of modules that may be imported without assignment. A
  package specifier is matched as written (`'foo/**'`, `'*.css'`); a relative
  or absolute one as the absolute path it names, against the glob as written
  (`'**/*.css'`) or relative to the working directory (`'src/styles/**'`).
- `devDependencies`, `optionalDependencies`, `peerDependencies`: in
  eslint-plugin-import's schema but never read there; accepted here, with no
  effect, so the config loads.
