Detect unescaped HTML entities in JSX. This rule is part of [`eslint-plugin-react-features`](https://www.npmjs.com/package/eslint-plugin-react-features).

## Quick Summary

| Aspect         | Details                                                              |
| -------------- | -------------------------------------------------------------------- |
| **Severity**   | Error (syntax)                                                       |
| **Auto-Fix**   | ✅ Yes (escapes entities)                                            |
| **Category**   | React                                                                |

| **Best For**   | All React/JSX projects                                               |

## Rule Details

A raw `>`, `"`, `'` or `}` in JSX text is reported, once per occurrence, with each
escape as a suggestion. The rule reads the source as written, so the escaped
spellings (`&quot;`, `&#34;`, `&apos;`, `{'"'}`) and characters inside attribute
values or string expressions are not reported.

### Why This Matters

| Issue                     | Impact                          | Solution                  |
| ------------------------- | ------------------------------- | ------------------------- |
| ⚠️ **Syntax errors**      | JSX parsing fails               | Use HTML entities         |
| 📖 **Readability**        | Ambiguous characters            | Explicit escaping         |
| 🐛 **Silent failures**    | Wrong output                    | Proper encoding           |

## Examples

### ❌ Incorrect

```tsx
<div>Use "quotes"</div>
<div>It's working</div>
```

`>` and `}` in JSX text do not parse in TypeScript, and the parser reports
them before this rule runs.

### ✅ Correct

```tsx
<div>Hello World</div>
<div>Use &quot;quotes&quot;</div>
<div>Use {'"'}quotes{'"'}</div>
<div>It&apos;s working</div>
```

### Entity Reference

| Character | Entity       | Alternative      |
| --------- | ------------ | ---------------- |
| `>`       | `&gt;`       | `{'>'}` or `&#62;` |
| `<`       | `&lt;`       | `{'<'}` or `&#60;` |
| `"`       | `&quot;`     | `{'"'}` or `&#34;` |
| `'`       | `&apos;`     | `{"'"}` or `&#39;` |
| `}`       | `&#125;`     | `{'}'}`          |
| `{`       | `&#123;`     | `{'{'}`          |

## Configuration Examples

### Basic Usage

```javascript
{
  rules: {
    'react-features/no-unescaped-entities': 'error'
  }
}
```

## Options

| Option   | Type                                                                | Default                 | Description |
| -------- | ------------------------------------------------------------------- | ----------------------- | ----------- |
| `forbid` | `(string \| { char: string, alternatives: string[] })[]` | `['>', '"', "'", '}']` | The characters to report. It replaces the default set. Each occurrence is reported where it stands, and an entry with `alternatives` suggests each one as a replacement |

## Known False Negatives

- `>` and `}` in JSX text are a parse error in espree and in the TypeScript
  parser, so the rule only sees them under a parser that accepts them (babel).
