Report a `catch` block that does nothing. An empty handler swallows the error: nothing is logged, nothing is rethrown, and the failure vanishes.

This rule is part of [`eslint-plugin-maintainability`](https://www.npmjs.com/package/eslint-plugin-maintainability).

## Quick Summary

| Aspect          | Details                              |
| --------------- | ------------------------------------ |
| **Severity**    | Error (code quality)                 |
| **Auto-Fix**    | ❌ No                                |
| **Category**    | Error-handling                       |
| **Suggestions** | ✅ Log, handle or rethrow the error  |

## Rule Details

The rule reports a `catch` clause whose body holds no statement: an empty block,
or one holding only empty statements (`;`). Every spelling of the clause counts:
with a binding (`catch (err) {}`), without one (`catch {}`), followed by
`finally`, inside an `async` function.

A catch block that does anything handles the error and is not reported: it logs
it, rethrows it, returns a fallback value, or records a flag for the caller.

## Configuration

| Option             | Type      | Default | Description                                                                                       |
| ------------------ | --------- | ------- | ------------------------------------------------------------------------------------------------- |
| `allowWithComment` | `boolean` | `false` | Accept an empty catch with an explanatory comment inside the block or within two lines above it   |
| `ignoreInTests`    | `boolean` | `true`  | Skip `*.test.*` / `*.spec.*` files                                                                |

With `allowWithComment`, a comment counts as an explanation when it uses one of
these words: `intentional`, `expected`, `ignore`, `silent`, `noop` / `no-op`,
`by design`, `known issue`, `legacy`, `third-party`, `framework`, `library`,
`not implemented`, `TODO`, `FIXME`. A comment far above the `try`, about
something else, explains nothing.

## Examples

### ❌ Incorrect

```typescript
try {
  data = readCache();
} catch (err) {}

try {
  await flush();
} catch {
  ;
}
```

### ✅ Correct

```typescript
try {
  data = readCache();
} catch (err) {
  console.error('cache read failed', err);
}

try {
  data = readCache();
} catch {
  return null; // a cold cache is a valid state
}

// With { allowWithComment: true }
try {
  data = readCache();
} catch {
  // intentional: a missing cache file means a cold start
}
```

## Configuration Examples

```javascript
// eslint.config.mjs
export default [
  {
    rules: {
      'maintainability/no-silent-errors': ['error', { allowWithComment: true }],
    },
  },
];
```

## Known False Negatives

The following patterns are **not detected**:

### Promise `.catch` with an empty handler

**Why**: the rule inspects `catch` clauses; `.catch(() => {})` is a function
argument, not a clause.

```typescript
// ❌ NOT DETECTED
save().catch(() => {});
```

**Mitigation**: give the handler a body that logs or rethrows.
