'eslint-plugin-modernization': minor

Three rules no longer report inside generated files: `conventions/no-magic-numbers`,
`conventions/no-commented-code` and `modernization/prefer-template-literal`.

Each one's remedy is unavailable in a file a generator owns. "Name this
constant", "delete this commented-out code" and "use a template literal" all
mean *edit this file* — and the next codegen run overwrites the edit. The
finding is correct and unactionable, which is the definition of an effective
false positive.

`no-magic-numbers` alone is the largest single source of findings on the pinned
corpus at 1421, and the project's triage already recorded it as "correct in
contract, and a taste rule by nature".

This is not a blanket exemption for generated code. A rule whose finding
describes what SHIPS — a hardcoded secret, a debug endpoint — still reports
there, because the artifact reaches production and the fix belongs in the
generator. The test is whether the finding can be acted on where it is raised.

Detection keys on the file's own `@generated` / `Code generated by …` banner,
not on a path convention.
